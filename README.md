# AstrBot NoReply

让机器人结合人设和群聊上下文，决定什么时候开口、什么时候保持沉默。

NoReply 不按固定概率抽签，也不要求每条消息都回复：同一次模型调用会对本批消息逐条判断，并生成需要发送的正文。普通群消息和 **@机器人** 共用一条链路，@ 消息不允许被判为沉默。

> **会产生模型费用。** 判断“不回复”和试运行也会调用模型。首次使用请限定一个群，先确认费用和效果；插件不提供每日费用封顶，也不保证供应商缓存命中。

## 功能

- **群上下文隔离**：按平台实例、机器人和真实群分别保存背景。默认每群最近最多 300 条观察，同群不同成员、普通消息与 @ 共用窗口，不串群。
- **忙时先入队**：消息先写入私有 SQLite；模型忙碌、发言冷却和正常重启不会静默丢弃已经成功入队的合格消息。
- **逐条批量判断**：默认一批最多 32 条待判，完整校验全部 ID、顺序、回复标记和正文后再提交。非法输出保留待判并退避重试，不冒充沉默。
- **按序发言**：只发送回复正文，不把内部 JSON 发进群。发送结果不明时暂停该群后续发送，不盲目重发。
- **身份与引用**：向模型提供发言者 ID、昵称、时间以及可用的机器人/管理员标记；管理员指 AstrBot 配置的管理员，不是群管理员。可用的引用文字可进入 @ 请求。
- **原生可视化配置**：人设下拉选择，群白名单、参与策略、节奏、上下文预算和诊断开关均在 AstrBot WebUI 设置。

## 支持范围

| 项目 | 范围 |
| --- | --- |
| Python | 3.12 或更新版本 |
| AstrBot | 本版本声明 `>=4.29.3`；实际回归基线为 4.29.3，不是固定生产依赖 |
| 消息平台 | 当前正式声明 QQ 官方适配器 `qq_official`；其他平台尚未完成相同等级的实机验证 |
| 模型 | 始终使用 AstrBot 为当前会话选择的聊天模型，需能稳定输出要求的 JSON；插件不另设模型覆盖 |
| 消息内容 | 文本为主；不识别图片和音频内容，不执行模型工具调用 |
| 依赖 | 无额外第三方运行依赖；使用宿主 AstrBot 及其 QQ SDK |

QQ 平台必须已经允许机器人接收相应普通群消息；如果平台只向机器人投递 @，插件无法判断未收到的消息。API/网络/供应商永久失败时，也不能保证待判一定会在有限时间内完成。

## 安装与首次配置

1. 在 AstrBot WebUI 的**插件**页面，通过 Git 仓库地址安装：
   ```text
   https://github.com/678mjoe/astrbot_plugin_noreply
   ```
   若插件已在市场上架，也可搜索 **AstrBot NoReply**。本地安装包可通过“从文件安装”导入。
2. 先在 AstrBot 配好聊天模型和人设，并确认目标来源的 AI 开关已打开。
3. 打开 **插件 → 已安装 → AstrBot NoReply → 配置**。出厂关闭插件、开启试运行、关闭全群、白名单为空，不会自动开放任何群。
4. 由 **AstrBot 管理员**在目标群发送 `/noreply_status`，复制返回的“白名单键”，填入插件的群白名单列表。QQ 官方格式是 `平台实例ID|qq_official|群OpenID`，不要用 QQ 群号代替 OpenID。
5. 下拉选择人设。模型统一在 AstrBot 原版配置中选择，插件沿用当前会话的选择。按需填写参与策略，例如：
   ```text
   只在有人明确求助，或讨论涉及编程时参与；避免重复附和。
   ```
6. 开启“启用自动群聊”，暂时保留“仅评估、不发言”。保存后，AstrBot 会热重载插件。确认调用量与状态，再关闭试运行以允许发言。

试运行也计费，且已接管的 @ 不会交回默认 Agent 另回复。不要长时间无监督地留在试运行。若已开启 AstrBot 原生的随机主动回复，请自行关闭重叠功能，避免双回和额外调用；本插件不会替你改写该设置。

## 常用设置

| 设置 | 出厂值 | 用途 |
| --- | --- | --- |
| 启用自动群聊 `enabled` | `false` | 总开关 |
| 仅评估、不发言 `shadow_mode` | `true` | 调用模型但不外发，包括已接管的 @ |
| 开放所有群 `all_groups` | `false` | 关闭时只使用准确白名单，空名单不开放任何群 |
| 群白名单 `allowed_groups` | `[]` | 用 `/noreply_status` 获取准确键 |
| 人设 `persona_id` | 空 | 必选，使用已有的人设 |
| 参与和回复策略 `reply_guidance` | 空 | 调整参与偏好及措辞，不覆盖输出协议与 @ 必回约束 |
| 近期背景条数 `window_messages` | `300` | 各群独立；待判消息单独保留 |
| 每批最多待判条数 `batch_size` | `32` | 范围 1～128，不是背景大小 |
| 判定最小间隔 `attempt_interval` | `10` 秒 | 可设 0 取消正常节流，仍保留失败退避 |
| 发言最小间隔 `reply_cooldown` | `30` 秒 | 是最小间隔，不是即时回复承诺 |

例如，重视实时性且已经确认预算时，可选 `attempt_interval=0`、`reply_cooldown=1`；模型耗时、同群串行及平台限制仍会影响实际响应速度。这不是出厂设置。

其余字符预算、超时、并发与诊断设置见 [完整配置说明](docs/CONFIGURATION.md)。不要在此插件内再填 API Key，密钥只在 AstrBot 的模型提供商设置中管理。

## 哪套 AstrBot 配置启用插件

消息使用哪套 AstrBot 配置，由原版的会话/来源路由决定。每套原版配置中的 **插件 → 可用插件**（`plugin_set`）控制是否向 NoReply 分发新消息；未禁用插件且列表为全部时，所有适用配置都可使用它。

插件自身的 `enabled`、`all_groups` / `allowed_groups` 再进一步控制总开关和接管群范围，来源 AI 开关关闭时也不接管。`all_groups=true` 不会绕过原版的新消息插件分发过滤。

**插件参数目前只有一份全局设置**，不会随 AstrBot 配置方案分别保存人设、背景长度或节奏。模型随原版会话选择；`persona_id` 仍使用插件选定的人设。

同一份原版可用插件列表也用于后台判定、发送前检查和原版背景屏蔽：方案禁用 NoReply 后，不再新增判定/发送，且不再屏蔽该方案的原版群背景。未开始的待判/待发队列暂停保留，重新启用可继续；禁用期间返回的生成结果不再排队外发。已经发出的模型请求或网络发送无法追溯撤回。

审阅项目请从 [发布前审阅单](https://github.com/678mjoe/astrbot_plugin_noreply/blob/main/RELEASE_REVIEW.md) 开始。

## 管理命令

| 命令 | 权限 | 作用 |
| --- | --- | --- |
| `/noreply_status` | AstrBot 管理员 | 查看当前群入队、待判、已判、取消、待发、API 确认和不确定发送数量，并获取白名单键 |
| `/noreply_clear` | AstrBot 管理员 | 清空当前群背景和待判，取消排队回复，放弃不确定项以解除阻塞；不重发旧正文，不撤回已发送消息 |

命令、私聊及未接管的消息保留原来的处理链路；已接管的非命令 @ 由插件负责，不再同时走默认 Agent。清空不能撤回已经在网络上的发送请求。

## 数据、发送与成本边界

- **本地数据**：必要队列位于 `data/plugin_data/astrbot_plugin_noreply/batch/queue.sqlite3`，包含近期/待判消息正文、判定及发送状态。即使完整诊断关闭，这份工作队列仍然存在。待判和未确认发送内容保留，普通旧正文随窗口淘汰释放；去重和覆盖元数据不会自动全部清理，需留意磁盘。
- **模型隐私**：所选群消息和人设会发送给所选模型服务商，请自行确认群成员知情及服务商的数据政策。不同群不共用消息背景。
- **诊断默认关闭**：开启后可能保存完整提示词和模型输出。不要把数据目录、数据库、诊断 JSONL 或真实群记录提交 GitHub。
- **可靠性不等于送达保证**：QQ 官方返回真实消息 ID 后记为 API 确认，不等于群成员实际看见。对超时/崩溃等结果不明的发送不自动重放；可明确识别的业务拒绝按规则延期处理。
- **不是完整 Agent**：此链路不执行工具、不识别多媒体、不与原版 Agent 会话数据库双向同步。只对接管群可撤销地屏蔽原版额外群背景，不清空原版历史。
- **缓存不作承诺**：包含前缀布局优化和缓存 token 观测；没有上线显式缓存管理。命中和计费取决于供应商，缺失的缓存字段显示为未知，不能当作 0 或已节费。

## 开发与发布

使用项目隔离环境运行离线测试，不需要生产密钥，也不要通过真实群发或收费模型调用验证文档变更：

```bash
uv sync --locked --group dev
uv run --locked pytest -q
uv run --locked ruff check .
python3 tools/verify_handoff.py
python3 tools/build_release.py
```

开发依赖中的 AstrBot 版本用于复现测试，不会替你更新或锁定生产实例。市场发布步骤及打包规则见 [发布说明](docs/PUBLISHING.md)，内部批量协议见 [设计说明](https://github.com/678mjoe/astrbot_plugin_noreply/blob/main/docs/BATCH_JUDGMENTS.md)。
