# 可视化配置说明

在 **AstrBot WebUI → 插件 → 已安装 → AstrBot NoReply → 配置** 修改。已有 `_conf_schema.json` 会由 AstrBot 自动渲染为表单；不需要独立网站或另一个管理端口。

模型使用官方 `select_provider` 选择器，人设使用 `select_persona` 选择器。白名单是字符串列表，**没有**把接收 UMO 的选择器误当作三元组群键。由管理员运行 `/noreply_status` 可以复制准确键。

当前 AstrBot 4.29.3 的配置保存服务会保存配置并热重载该插件。若直接手改配置文件，尤其修改节流、超时、窗口等 Limits 参数，请手动重载插件；仅改文件不代表内存中的旧引擎已经更新。

## 所有配置项

### `enabled` — 启用自动群聊

- 类型：`bool`；默认值：`false`。
- 需要同时选好人设和群范围。群消息会发送至所选模型服务商；判断沉默也会消耗额度。

### `shadow_mode` — 仅评估、不发言（仍计费）

- 类型：`bool`；默认值：`true`。
- 开启后仍调用模型并保存判定，但不外发回复，包括已接管的 @ 消息。确认效果与费用后再关闭。

### `all_groups` — 开放所有群

- 类型：`bool`；默认值：`false`。
- 默认关闭。开启后不再使用群白名单，但仍遵守来源配置的 AI 开关；请先确认各群成员知情。

### `allowed_groups` — 群白名单

- 类型：`list`；默认值：`[]`。
- all_groups 关闭时生效。逐项填写 平台实例ID|机器人ID|真实群ID。QQ官方适配器用 平台实例ID|qq_official|群OpenID，不是 QQ 群号；空列表不开放任何群。

### `persona_id` — 人设（必选）

- 类型：`string`；默认值：`""`。
- 选择 AstrBot 中已创建的人设；留空或人设不存在时不调用模型，不会自动改用其他人设。

### `provider_id` — 模型（留空跟随当前会话）

- 类型：`string`；默认值：`""`。
- 可选择已有的聊天模型提供商；留空时沿用 AstrBot 对该来源的模型选择。此处只保存提供商ID，不填写API Key。选择无效模型时不静默回退到其他模型。

### `reply_guidance` — 参与和回复策略（可选）

- 类型：`text`；默认值：`""`。
- 例如：仅在有人明确求助，或讨论涉及编程时参与；避免重复附和。留空时使用人设与内置规则。只控制参与偏好和措辞，不覆盖批量JSON协议及 @必回约束。

### `window_messages` — 近期背景条数

- 类型：`int`；默认值：`300`。
- 每个物理群独立保留的近期观察上限；默认300条，用户及机器人自己的观察共用窗口。待判消息单独保留，不会被窗口淘汰。窗口越大，输入费用通常越高。修改后重载插件。

### `message_chars` — 单条观察字符上限

- 类型：`int`；默认值：`0`。
- 0 表示不截断；正值限制每条发给模型的正文字符数。修改后重载插件。

### `context_chars` — 观察JSON字符预算

- 类型：`int`；默认值：`0`。
- 0 表示不限制；正值必须至少512。超限先缩减旧背景，待判过大则拆小重试，不悄悄丢掉待判ID；不含人设和内置系统协议。修改后重载插件。

### `attempt_interval` — 判定最小间隔（秒）

- 类型：`float`；默认值：`10.0`。
- 默认10秒，可设0以取消正常判定节流；仍保留同群串行、失败退避与模型耗时。这不是回复间隔。修改后重载插件。

### `reply_cooldown` — 发言最小间隔（秒）

- 类型：`float`；默认值：`30.0`。
- 默认30秒，可按需调小。仅是同群发言的最小间隔；生成、失败退避和平台限制可能使实际等待更长。不会因此丢掉已入队消息。修改后重载插件。

### `timeout` — 单次操作超时（秒）

- 类型：`float`；默认值：`30.0`。
- 必须大于0。用于模型调用及发送操作；模型超时保留待判，发送结果不明时不盲目重发。修改后重载插件。

### `max_reply_chars` — 单条回复字符上限

- 类型：`int`；默认值：`600`。
- 必须至少1；超过上限的模型正文不会被直接外发，而会作为非法批次重试。修改后重载插件。

### `max_groups` — 最大并发群worker数

- 类型：`int`；默认值：`128`。
- 必须至少1。是并发工作数，不是可用群数量上限；更多群继续持久排队。高并发可能增加供应商限流和费用。修改后重载插件。

### `diagnostics_enabled` — 完整私有诊断（谨慎开启）

- 类型：`bool`；默认值：`false`。
- 会额外保存输入、完整人设/提示词、模型回复等敏感内容，默认关闭。日志只能留在本地私有数据目录；不要随问题反馈公开上传。关闭不会自动删除旧文件。

### `batch_mode` — 旧版兼容：持久化批量模式

- 类型：`bool`；默认值：`true`。
- 请保持true。false是旧快照算法，不保证逐条覆盖，@处理也不同；仅供旧版兼容，不建议普通用户切换。

### `batch_size` — 每批最多待判条数

- 类型：`int`；默认值：`32`。
- 范围1～128，默认32。实际批次可能因待判量、退避或非法输出而更小；数字不是背景窗口大小。

### `batch_retry_base` — 失败初始退避（秒）

- 类型：`float`；默认值：`5.0`。
- 范围大于0且不超过60，默认5；失败项指数退避最长60秒，不把失败当作沉默。

## 设置建议

- **首次使用**：保持单群白名单和试运行，选择人设；试运行只做短时检查，因为仍计费。
- **成本优先**：缩小背景窗口、选择合适的模型、保留判定间隔，并在服务商侧设置预算/限流。发言冷却只控制发言，不是模型费用上限。
- **实时优先**：在已确认预算和模型吞吐后，可取消判定间隔、缩短发言冷却。一次调用可能判断多条消息，不代表每条消息都要另开一次调用。
- **控制语气**：优先使用人设；需要调整参与条件时填 `reply_guidance`，不要要求其覆盖必回策略或内部 JSON 信封，否则可能造成反复非法输出和额外费用。
- **兼容旧配置**：原有平铺键与出厂默认值不变。新 `provider_id`、`reply_guidance` 缺失时补空值，保持原来的路由与提示词；`batch_mode` 仍可被旧配置读取，但隐藏于普通 UI，不建议关闭。
