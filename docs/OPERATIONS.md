# 部署定位与放行边界

## 已有运行环境，仅供理解

- AstrBot 运行在 Pi，工作目录 `~/astrbot`，用户服务 `astrbot.service`。
- 最近核实的面板是 `http://172.16.0.71:6185/`。蒲公英账号已变更，SSH 别名由用户维护；地址可能再次变化，不能据此硬编码远端发送路径。
- Mac Magpie 已指向 Pi 新地址；这不表示本项目应修改 Magpie 或将其默认选为插件模型。插件通过 AstrBot 当前来源的 Provider API 选择模型。
- 本仓库在 Mac `~/projects/astrbot_plugin_noreply`，不是运行实例的 plugins 目录。

## 版本变动

Pi 上 AstrBot 可能更新。4.29.1 只是交接时的观测和回归基线，不是运行版本约束。部署前从实际服务运行环境重新核验版本与关键接口；升级后先验证兼容性。不得自行给服务添加版本锁、降级或升级命令。当前版本未验证时明确记录，不宣称可上线。

## 当前授权

可以写代码、项目内安装开发依赖和跑离线测试。未授权修改 Pi 实例、安装插件到真实服务、改账号/路由/监听、重启服务、复制密钥或真实聊天记录。

真实 shadow 仍会调用模型，不属于纯离线测试。M2 前请用户确定测试模型、人设与测试群，并明确放行调用、安装和必要重启；不能把一次泛泛的“继续开发”当成所有上线操作的许可。

## 后续部署验收应包含

- 备份插件及要修改的精确配置；确认内置随机主动回复和其他插件是否竞争。
- 先保持 enabled=false / shadow=true，再在批准的单群观察。
- 对端实际收件、无标签泄漏/重复回复、正常 @ 与命令回归。
- 关闭开关与卸载后迟到结果不发出；失败有可读日志。
- 不以 after_message_sent 钩子作为可靠送达回执，不承诺 exactly-once。
- 需要 root 时列出精确命令等待用户，不自行变通。
