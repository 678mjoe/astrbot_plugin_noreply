# M2：单群在线验收

## 当前授权与安全范围

用户已明确允许在专用测试群进行在线测试，并提供该群 UMO。可以安装/加载本插件并调用该群当前模型，使用已有 `default` 人设；不得扩大到其他群、改模型路由或把密钥/真实群标识/聊天正文放进仓库。先做限时 shadow，真实发送另作为下一验收点，不因已安装而宣称 M2 完成。

出厂配置继续保持关闭、shadow、空白名单。`templates/m2-shadow-disabled.json` 是保守参数的待配置模板，不是真实实例配置。

## QQ 官方机器人必须先核实的两件事

1. 未 @ 消息能否进入 AstrBot。当前安装的 QQ 官方适配器含 `on_group_message_create()`，不是“官方机器人永远只能收到 @”。[QQ 官方文档](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/group_message_create.html)规定：群启用“接收所有消息”后才推送 `GROUP_MESSAGE_CREATE`。实际群是否已获授权/开启，需要群主设置或真实收件验证，不自行改变群权限。
2. 精确白名单不是普通 QQ 群号。UMO 中的真实群 OpenID 与适配器的 self_id 才是匹配依据。当前适配器未 @ 的纯文本可能使用 `qq_official` 作为 self_id 哨兵；不要把 QQ 号或 AppID 想当然填进去。实际测试仅配置用户明确提供的群，真实值留在私有运行配置。

## 运行顺序

1. 私有备份运行配置及数据库；安装包严格只含 `main.py`、`engine.py`、`diagnostics.py`、`native_context.py`、`metadata.yaml`、`_conf_schema.json`、独立运行说明 README，不带开发环境、快照、运行数据或密钥。
2. 先保持 shadow=true。真实群白名单仅一项，沿用原始 UMO 的 Provider 选择，不改全局/群路由。
3. 本轮试验限定为一个短窗口，尝试间隔 60 秒；到期停止本插件试验。时间窗口和低频限制用于约束开销，不能宣传成 Provider 内部绝对请求/计费上限。
4. 检查框架成功加载、面板可达、原插件与普通 @/命令仍在。只允许必要的 AstrBot 服务操作，不动 Hermes/Magpie。
5. 在测试群发未 @、非命令、纯文本；检查 `decision=silent/shadow/invalid/error/timeout` 等统计。默认不保存正文、完整模型响应或用户 ID。`shadow` 表示通过文本协议但没有发送，不等于质量满意。
6. 若看不到事件，优先核实群的“接收所有消息”与精确身份匹配；不要提高概率、乱改模型或拿 @ 对话冒充未唤醒验证。
7. 实际发送阶段另记结果：单群收到正文、无控制标签/重复、@与命令不多调模型、关闭与清空后无迟到结果。模型选择沉默可能合理，不将每条都回复当作合格标准。
